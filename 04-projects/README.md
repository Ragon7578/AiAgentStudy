# 实战项目

概念和示例跑通后，选一题独立完成。目标不是「堆框架」，而是把闭环做稳。

## 项目 A · 个人知识库问答 Agent（推荐入门）

**目标**：对本地 `notes/` 目录里的 Markdown 做问答。

**要求**

1. 工具 `list_notes`：列出笔记文件  
2. 工具 `read_note`：读取指定文件内容  
3. Agent 循环：先列目录，再按需阅读，最后回答  
4. 限制只能读 `notes/` 下文件（防路径穿越）  
5. 最大步数 ≤ 8  

**验收**：问「笔记里关于 Agent 记忆的要点是什么？」能引用文件作答。

**提示**：可从 [03-react-agent](../03-examples/03-react-agent/) 复制循环骨架。

## 项目 B · Git 仓库小助手

**目标**：在当前 git 仓库回答「最近改了什么 / 谁改的」。

**要求**

1. 工具封装只读命令：`git log`、`git status`、`git diff`（禁止 `push` / `reset --hard`）  
2. 命令白名单 + 超时  
3. 用中文总结变更  

**验收**：`最近三次提交做了什么？` 得到可读摘要。

---

## 项目 C · 多 Agent 写大纲

**目标**：两个角色协作产出学习大纲。

**角色**

- 研究员：负责要点列表（可假装搜索或读本地文件）  
- 编辑：把要点整理成带层级的 Markdown 大纲  

**要求**

1. 流水线：研究员输出 → 编辑输入  
2. 固定中间 JSON schema（例如 `{"bullets": [...]}`）  
3. 打印两段角色的原始输出，便于调试  

**验收**：输入「AI Agent 入门」，得到一份可放入 README 的大纲。

## 提交建议

在本仓库新建目录，例如：

```
04-projects/my-notes-agent/
  README.md      # 怎么运行、学到了什么
  main.py
  notes/         # 样例笔记
```

写清：

- 用了哪些工具  
- 停止条件是什么  
- 踩过的坑（工具描述、死循环、幻觉）  

## 自评清单

- [ ] 没有 API Key 时有友好报错  
- [ ] 工具失败时模型能看到错误并换策略  
- [ ] 有最大步数  
- [ ] 危险操作被禁止或需确认  
- [ ] README 别人能按步骤跑通
