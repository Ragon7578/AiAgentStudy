# 04 · 记忆（Memory）

Agent 的「记忆」不是人脑记忆，而是：**什么信息、以什么形式、在何时放进模型上下文**。

## 三类记忆

### 1. 短期记忆（对话 / 轨迹）

当前任务里的消息与工具调用记录。

- 优点：实现简单  
- 缺点：窗口有限，长任务会爆  

技巧：只保留最近 N 轮，或把中间步骤压缩成摘要。

### 2. 长期记忆（跨会话）

存在数据库 / 向量库 / 文件里，例如：

- 用户偏好：「喜欢简洁中文回复」  
- 项目事实：「这个仓库用 pnpm」  
- 历史结论：「上次排查是 Redis 超时」  

取出时再注入提示词。

### 3. 工作记忆（Scratchpad）

任务进行中的便签：待办列表、已验证假设、当前假设。  
ReAct 里的 Thought 轨迹也属于这类。

## 常见实现方式

| 方式 | 适用 |
|------|------|
| 全量消息列表 | 短对话 |
| 滑动窗口 | 中等长度任务 |
| 摘要压缩 | 长对话、长 Agent 轨迹 |
| 向量检索（语义记忆） | 大量历史笔记 / 文档 |
| 键值记忆（结构化） | 用户画像、配置项 |
| 实体记忆 | 人物、项目、工单等对象 |

## 一个实用模式

```
每次回合：
1. 从长期记忆检索与当前目标相关的 3～5 条
2. 拼进系统提示或单独的 "Memory" 消息
3. 跑 Agent 循环
4. 任务结束后，把「值得记住」的结论写回长期记忆
```

「值得记住」要有规则，否则会存一堆噪音。

## Agent 健忘的常见原因

1. 上下文被截断，早期工具结果丢了  
2. 系统提示太长，挤掉了关键事实  
3. 多 Agent 之间没有共享状态  
4. 只记对话原文，没有结构化事实  

## 设计建议

- 把**稳定事实**（技术栈、账号环境）和**临时过程**（某次搜索片段）分开存  
- 对 Coding Agent：仓库结构、约定、失败命令比闲聊更重要  
- 对客服 Agent：订单号、用户等级比寒暄更重要  
- 默认：**少记、记准、可检索**
