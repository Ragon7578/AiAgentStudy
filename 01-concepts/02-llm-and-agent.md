# 02 · LLM 与 Agent 的关系

## LLM 只是「大脑」

大语言模型（LLM）擅长：

- 理解自然语言指令  
- 做推理、分类、总结、写代码  
- 按约定格式输出（JSON、函数调用参数）  

但它**默认**：

- 不知道「现在几点」  
- 读不到你的本地文件  
- 不能真的发邮件、下单、改数据库  

这些能力要靠 **Tools** 接上。Agent 框架负责：把工具描述给模型 → 解析模型要调用的工具 → 执行 → 把结果塞回对话。

## 上下文窗口 = 短期工作记忆

模型一次能「看见」的 token 有限（如 128K）。Agent 运行时上下文通常包括：

```
系统提示（人设 + 规则）
+ 可用工具列表
+ 对话历史 / 中间步骤
+ 检索到的资料（RAG）
+ 当前用户目标
```

上下文一满，早期步骤会被截断 → Agent「忘事」。所以需要记忆策略（见 [04-memory](./04-memory.md)）。

## 提示词在 Agent 里的角色

系统提示通常规定：

1. **角色**：你是代码审查助手  
2. **目标**：找出 bug 与风险，给出可执行建议  
3. **工具使用规则**：何时必须查文件、何时直接回答  
4. **输出格式**：先结论后细节；不确定要标明  
5. **安全边界**：不泄露密钥、不执行危险命令  

好的 Agent ≈ 好的模型 + **清晰边界的提示** + 可靠工具。

## 函数调用（Function Calling / Tool Use）

现代模型支持「结构化调用工具」：

```json
{
  "name": "get_weather",
  "arguments": { "city": "上海" }
}
```

不是让模型「假装」调了工具，而是框架**真的执行**函数，再把返回值作为下一条消息喂给模型。

这是 Agent 从「聊天」变成「干活」的关键能力。详见 [03-tools](./03-tools-and-function-calling.md)。

## 模型怎么选（学习阶段）

| 场景 | 建议 |
|------|------|
| 本地免费练手 | Ollama + 支持工具的开源模型 |
| 中文 + 性价比 | DeepSeek、通义千问 等 |
| 复杂推理 / Coding Agent | 强推理模型（如 GPT / Claude 系列） |
| 要稳定 JSON / 工具调用 | 优先选明确支持 function calling 的模型 |

学习阶段：**先跑通闭环**，再纠结模型排名。
