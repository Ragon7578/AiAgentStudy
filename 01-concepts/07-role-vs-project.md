# 07 · 角色优先：重新设计 Agent 的节奏

> 学习语境下：「项目」= **练习剧本 / 上场场景**，不是业务产品仓库。  
> AiAgentStudy 本身是学习工具；练的是拆法，不是交付某个 App。

## 两种拆法

| 拆法 | 你怎么切 | 问题 |
|------|----------|------|
| **按项目拆**（旧习惯） | 知识库 Agent、Git Agent、大纲 Agent… | 角色重复造轮子；换项目就要重写一整只 Agent |
| **按角色拆**（推荐） | 研究员、编辑、审查员、编码员… | 项目只负责「场景 + 材料」，角色可复用 |

一句话：

> **角色是能力模板；项目是上场剧本。**  
> 先定角色，再用角色去拼项目。

## 新节奏（四拍）

```
1. 定角色 Role
      │  职责、工具权限、输入输出格式
      ▼
2. 选项目 Project
      │  目标、材料（仓库/笔记）、约束
      ▼
3. 组装 Cast
      │  这个项目需要哪些角色？谁先谁后？
      ▼
4. 上场 Run
         注入「项目上下文」，角色按流水线/主管模式执行
```

## 角色里放什么 / 不放什么

**角色（稳定、可复用）**

- 人设与职责：「你只做调研，不写最终文案」  
- 可用工具范围：只能读、不能推代码  
- 输入 / 输出协议：必须产出 `{"bullets":[...]}`  
- 停止条件与质量标准  

**项目（易变、一次一境）**

- 本次目标：「为 AiAgentStudy 写大纲」  
- 材料路径：`notes/`、某个 git 仓库  
- 截止时间、语言、受众  
- 额外禁区：「不要改 main」  

换项目时：**尽量只换项目上下文，不动角色卡。**

## 对照例子

### 旧：按项目拆

```
agents/
  notes_agent.py      # 又当检索又当回答
  git_agent.py        # 又当查询又当总结
  outline_agent.py    # 又当调研又当编辑
```

三个文件里，很多提示词和循环逻辑是重复的。

### 新：按角色拆，再拼项目

```
roles/
  librarian.md        # 只会列目录/读笔记/引用回答
  git_analyst.md      # 只会只读 git 查询
  researcher.md       # 只会产出要点 JSON
  editor.md           # 只会把要点编成大纲
projects/
  knowledge-qa/       # 启用：librarian + 项目材料 notes/
  repo-digest/        # 启用：git_analyst + 当前仓库
  outline-pipeline/   # 启用：researcher → editor
```

## 角色能跨项目吗？

能。这正是重点：

| 角色 | 项目 A 知识库 | 项目 B 仓库周报 | 项目 C 学习大纲 |
|------|---------------|-----------------|-----------------|
| librarian | ✓ | | 可选读教材 |
| git_analyst | | ✓ | |
| researcher | | 可选 | ✓ |
| editor | | 润色周报 | ✓ |

同一个 `editor`，昨天润色周报，今天整理大纲——**角色不变，项目上下文变。**

## 什么时候仍可以「一项目一 Agent」？

任务极简单、永远单人完成、也不打算复用时，可以先做一个综合 Agent。  
但一旦出现第二个相似项目，就应**抽出角色**，避免复制粘贴。

## 设计口诀

1. **先角色，后项目**  
2. **一角色一职责**  
3. **项目 = 角色清单 + 材料 + 目标**  
4. **跨项目复用角色，不复用「整只大杂烩 Agent」**
